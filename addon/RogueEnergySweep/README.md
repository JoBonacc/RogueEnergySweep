# Rogue Energy Sweep v0.16.0 — release candidate
Target: World of Warcraft: Forever 1.60.1, Interface 16001.

## Installation and options
Replace the old `RogueEnergySweep` folder under `Interface/AddOns/` with the folder in this ZIP. Your saved variables are retained. Reload the UI (or restart the client), log into a Rogue, and type `/resweep` to open the options panel. The panel is also registered under Settings > AddOns > Rogue Energy Sweep. All settings apply immediately and persist across reloads. Settings are grouped into Behavior, Animation style, Progress mode, Appearance and Preview. Tint is shown only for Rising Line; thickness is shown for Rising Line, Bottom Bar and Perimeter, not Radial Sweep. Hidden controls preserve their saved values.

## Four indicator styles
- Rising line: a bright horizontal stripe rises up the icon; optional faint tint below it. Default for new installations and former Auto mode. If the fill-edge anchor is unavailable, a vertical fill is used instead.
- Bottom bar: fills left to right against a dark track.
- Perimeter: fills clockwise along the top, right, bottom, and left edges.
- Radial sweep: legacy deficit shading, with native default full-circle geometry restored from v0.1.0. Reported working in the v0.7.0 animation smoke test; current release candidate requires retesting.

All four indicators support two progress modes. Energy-based (default) shows the fraction of the ability cost accumulated. Countdown (experimental) starts at zero progress using a post-spend snapshot and fills toward affordability: after spending 45 of 60 energy, the next 45-energy ability progresses from 0% at 15 energy to 50% at 30 energy and disappears at 45. The sweep shows the remaining fraction. Another spend restarts the countdown for affected abilities; a refund advances it. All indicators disappear at affordability. Both modes follow actual energy rather than a fixed time estimate. The options preview has a second slider in countdown mode for post-spend starting energy. The standard cooldown/GCD is not modified. The new options panel has eight color swatches, a native custom RGB color picker with live preview and cancel restoration, opacity (15–100%), indicator thickness (2–8 UI units; linear indicators), optional rising fill tint, combat-only and enable switches, three sample icons with a simulated energy slider, a five-second action-bar test, and reset defaults.

## Finisher filtering
Enable **Finishers only with combo points on target** to hide energy overlays on finishers unless your current target has at least one combo point. Works independently of style and progress mode. Known ranked finishers and spells with a required combo-point cost are detected; other abilities are unaffected. Target swaps and combo-point events refresh the display. The setting defaults off; the demo and simulated preview ignore this gate. If target-specific combo points cannot be displayed safely, finisher overlays are hidden rather than showing stale points. `/resweep status` reports the gate source and number of detected finishers. Protected-value behavior needs live verification.

## Ability filters
Use **Ability filters...** to select known combo-point builders, finishers and other/utility abilities, or uncheck individual discovered energy abilities. Unknown and conditionally generating spells are grouped under Other rather than guessed; category filters are enabled by default (show all). A category-hidden ability retains its individual preference. Exclusions apply by spell ID to all matching buttons and are saved; new ranks may need to be excluded separately. **Hide on cooldown (ignore GCD)** uses native spell cooldown duration objects to suppress overlays on cooldown, excluding the global cooldown. If unavailable, effects remain visible. Both filters are optional, default off/empty, and bypassed by the demo. The preview is unaffected. Live verification is pending.

## Appearance and preview
Each style remembers its own color, opacity, thickness, direction, tint and tint opacity. Existing shared values are copied to all four styles on upgrade. **Reset style** restores only the current appearance; **Reset all** requires confirmation in options. Reverse direction is available for all four animations. Rising fill tint has independent opacity (relative to the main opacity), and three fill effects: Solid (original), Gradient (soft fade toward the trailing edge), and Luminous (additive gradient and leading stripe). Fill effects appear only when Rising Line tint is enabled, follow direction and both progress modes, and are saved per style. Solid is the migration default. Unsupported gradient/blend APIs fall back to solid; the diagnostic report counts affected buttons. Animate runs a simulated 10 energy/sec regeneration cycle in the preview and stops at 100, on manual slider changes or when closing the settings. It does not change live energy or cast spells.

## Diagnostics
Use **Diagnostics** or `/resweep diagnostics` to open a selectable report. Click Select report and press Ctrl+C; WoW does not permit addons to write directly to the system clipboard. Review before sharing. Start sampling enables session-local timing of addon update callbacks; stop retains the sample. Reported memory is a client estimate and timing is not a full frame-rate/CPU profiler. No profiling is enabled by default. Actual performance and live compatibility still require in-game validation.

## Energy ready effects
Open **Ready effects...** in the Progress mode row. None (default), Cast burst, Cooldown flash, Proc glow, Halo, Border, Pulse, and Soft flash are global choices independent of the active regeneration style. Match indicator color and effect intensity are optional. Persistent effects use a native readiness curve, separate from regeneration alpha. One-shot effects use an explicitly public energy transition or, for non-finishers, a conservative public spell-power usability transition when available. If neither is readable, the optional (default enabled) pulse fallback appears while affordable; disabling it suppresses the one-shot effect in those cases. No protected values are compared, guessed, or read back. The preview always uses public simulated energy and can demonstrate the one-shot artwork. Filters apply to the live ready gate. Missing artwork or animation API support can fall back to a simple effect. The diagnostic report identifies the actual path and errors. Native artwork and animation calls still need live verification. Energy-ready does not imply range, target, or other cast requirements are met.

## Commands
- `/resweep` or `/resweep options`: open options.
- `/resweep demo`: display 50% progress for five seconds on tracked buttons (out of combat only).
- `/resweep status`: display renderer counts, curve source, last caught API error and interface compatibility.
- `/resweep mode rising|bar|perimeter|radial`: change style.
- `/resweep progress energy|countdown`: switch progress mode across all four styles.
- `/resweep color amber|white|cyan|green|red|purple|orange|black` or `/resweep color #RRGGBB`: change color. The legacy black preset uses white in linear styles; a custom RGB color applies exactly to every style. Opacity is separate. If the native picker is unavailable, use the hex command.
- `/resweep opacity 90`: change opacity.
- `/resweep diagnostics`: open the diagnostic report.
- `/resweep profile on|off`: start/reset or stop the update sampler.
- `/resweep reverse`: reverse the active style.
- `/resweep tintopacity 15`: set rising tint opacity (0–100).
- `/resweep fill solid|gradient|luminous`: change the active Rising Line fill effect.
- `/resweep ready`: open energy ready settings.
- `/resweep ready none|burst|flash|proc|halo|border|pulse|softflash`: choose ready effect.
- `/resweep resetstyle`: reset only active appearance.
- `/resweep thickness 4`: change line/bar thickness.
- `/resweep finishers on|off`: enable or disable target combo-point filtering (omit argument to toggle).
- `/resweep filters`: open individual ability filters.
- `/resweep cooldowns on|off`: toggle cooldown filtering.
- `/resweep combat`: toggle combat-only.
- `/resweep on` / `/resweep off`: enable or disable.
- `/resweep rescan`: rediscover action buttons.
- `/resweep reset`: restore defaults.

## Patch and update alerts
At login the addon also compares the client build (second GetBuildInfo return) with reviewed baseline 71091 and warns once per newer build. /resweep status displays the running build, baseline and last fully live-tested build (not recorded). At login the addon compares the fourth return from `GetBuildInfo()` with its target interface (16001). A mismatch warns once per distinct interface/target pair in saved variables, without disabling the addon. `/resweep status` always reports the current compatibility state when available. A matching interface is not proof of live compatibility; patches can change behavior without changing the interface number. WoW addons cannot query GitHub for updates themselves. Check the repository Releases page or use WowUp's Install from URL with https://github.com/JoBonacc/RogueEnergySweep for external updates.

## Compatibility and limitations
Blizzard action buttons are the primary target; Bartender4, Dominos, and ElvUI are best effort. Macro support depends on whether the client exposes the underlying spell through `C_ActionBar.GetSpell`. Cost changes depend on the client exposing public costs. Maximum energy defaults to 100 until a public value is available. New non-main-bar buttons may wait for combat to end. Resource events are coalesced at 30 ms; smoothness depends on the client. In-game visual layout, the rising line anchor, cooldown layering, full radial geometry, native secret-value alpha acceptance and actual taint safety are not confirmed by simulation. If a renderer fails, the addon tries the bottom bar; if native alpha or value rendering fails there too, it hides the overlay. Run `/resweep status` and capture any Lua error if something is missing or behaving unexpectedly.

Uses native curves for readiness, deficit, and visibility, with public arithmetic fallback when energy is explicitly non-secret. Native widget methods consume protected curve outputs. Does not perform arithmetic on protected energy values or change secure action button attributes.

Countdown implementation: public energy uses changes in the energy fraction to detect spending. Protected energy uses successful player spellcasts to request a fresh snapshot on the next coalesced update; if the spell identity/cost is protected, a successful non-energy cast can also reset the display. An energy loss not accompanied by a successful cast may not restart the protected countdown; cast/power event order can also affect the snapshot. Protected countdown now passes the post-spend snapshot directly to native status bar ranges, without reading back a radial texture. Bottom and rising use native linear ranges, radial uses a native radial status bar, and perimeter uses four clipped bars with the same full range. If a widget rejects the protected range or clipping is unavailable, that button falls back to energy-based progress until a new snapshot or style change. Options and `/resweep status` show actual progress state and per-button API errors. Native direct range is experimental; successful calls do not prove visual output, and perimeter clipping may be unavailable in Forever. Failed cast attempts do not restart the countdown.

Historical validation of v0.3.0 (not rerun for v0.4.0): 26 simulated Lua tests passed in a Lua 5.4 runtime, including existing action discovery behavior, all four modes with simulated secret values, clearing at readiness, options registration and controls, settings updates, preview thresholds, both progress modes, protected snapshot normalization, restart behavior, and safe fallback. This is not a live-client test.

## Energy Tracker
Open **Energy Tracker...** or `/resweep tracker`. Enable the optional standalone display, choose Dial, Bars, Icons, Freeform or Rings (nested groups of up to four per cluster), and optionally disable action-bar overlays. Unlock to move the group; Freeform supports dragging individual icons. Settings include size, scale, spacing, color, opacity, cost labels, bar/ring names, selection, ready effects, and hiding affordable rows (except Dial, which retains markers). Icons have independent animation style; ability progress inherits the global energy/countdown choice. Dial always shows actual energy, with static cost markers and native radial progress. Numeric energy is shown only when publicly readable. Ability selection is based on discovered action-bar spells; manually selected off-page spells are retained when still known. Existing filters apply to both displays. Native radial alignment and visual behavior require live testing. No clicks cast spells; locked frames do not receive mouse input.

## Ability Chains and GCD-aware readiness
`/resweep chains` opens per-ability repeat and follow-up pip rules. Circles show repeat affordability (optional partial next pip); diamonds show alternative follow-ups, not additive promises. Templates replace rule overrides. Defaults off; configurable assumed energy per GCD (10 by default), not cooldown or combo forecasts. `/resweep gcd on` enables experimental GCD-aware readiness when remaining GCD and regen are public and the spell is confirmed on-GCD; otherwise actual energy is used. Countdown progress itself remains actual-energy based. See diagnostics.

### Energy Breakpoints
Select Segments, Staircase, Lights, or Arc in Energy Tracker. Cost thresholds are unique and automatically sorted from tracked spells and current talent-adjusted costs; use manual selection for fewer markers. Shared gauges display actual energy and keep geometry fixed when cooldown or combo states change. The arc uses the native radial fill with static separators, rather than a separate cropped ring for every segment. The GCD option also applies to individual tracker rows/icons/rings, not shared gauges.

### Energy Arsenal
Select Arsenal in Energy Tracker (`/resweep tracker arsenal`). Choose Circles, Diamonds, Charges or Counts, plus the Vertical stacks checkbox for columns. Optional icons, ability names and costs can all be hidden. Counts use public numeric energy only and fall back to native pips when restricted; the layout stays fixed. Select abilities via the existing tracker picker. Color assignments, assumed energy per GCD, partial pips, inactive visibility, maximum repeats and explicit repeat rules come from Ability Chains (`/resweep chains`) even when action-button Chains is disabled. Builders default to repeat counts; non-builders default to one pip, unless a repeat rule or Repeat all (energy only) is enabled. All rows are alternative energy budgets, not additive charges or promises of actual castability. Individual spell/category exclusions apply; cooldown and combo gates do not alter these energy-only budgets. Lock the tracker after moving it. Live rendering verification pending.

### Follow-up conditions and global reservations
In Ability Chains, select a source ability, then cycle each local follow-up button through Off, + (opportunity), ! (warning). A warning shows a target-colored exclamation diamond only when the source is affordable but the target would be unaffordable after the assumed GCD regeneration. Choose a target ability in the main selector and cycle Global: Off / Opportunity / Warning to apply that relationship on all other tracked spending abilities. `/resweep chains kick` enables the global Kick warning if Kick is discovered. Up to three globals and three visible follow-ups per button; global warnings take priority, then global opportunities, then local rules. Global rules override duplicates, survive template changes, and retain the same ability colors. Optional Pulse warnings; inactive warnings are always hidden. Existing follow-ups stay positive. Target cooldowns, refunds, combo points, and actual GCD duration are not modeled; configure the existing assumed regeneration setting. Live visual testing pending.

## Unified settings (v0.20.0)
`/resweep` opens one task-oriented settings window. Action bars contains readiness style, preview, appearance, behavior, ready effects and ability filters. Energy HUD groups layouts by purpose with visual thumbnails and contextual settings. Ability planning contains repeat/follow-up rules, a direct Kick reservation toggle, global rules, templates and appearance. Advanced contains master/combat switches, regeneration, profiling, diagnostics and reset. Quick setup enables a feature without resetting other settings. `/resweep tracker`, `/resweep chains`, `/resweep filters` and `/resweep ready` navigate directly to the relevant page. Action-bar sweep and planning pips are independent; master enable and shared filters still apply. Existing preferences are preserved. `/resweep legacy` opens the old controls if necessary. Live layout verification pending.

The planning page's consecutive-use switch hides repeat circles on action buttons without altering follow-up warnings or the standalone cast-count HUD.

GCD-aware readiness (v0.20.1): when exact projection is unavailable, known GCD-bound abilities suppress sweep/ready visuals during a confirmed GCD rather than flashing a transient deficit. Native opaque duration or a public active flag is preferred; a bounded event-based hold is a last resort. Shared energy gauges and planning pips remain actual-energy based. Unknown abilities remain conservative. Diagnostics include cumulative projection/hold counts.

GCD-aware readiness (v0.20.2): supersedes the v0.20.1 visual-hold behavior. Only measured public timing and regen are used; otherwise actual energy stays visible. Prefer Forever's 29515 GCD source; see diagnostics for availability. No estimated GCD or blanket suppression.

## v0.21.0 planning
Repeat pips on action buttons now default to additional casts (first full pip = second affordable cast). Switch in Ability planning > Consecutive casts or `/resweep chains total` / `/resweep chains additional`. Arsenal still counts total casts. Pip appearance adds inside/outside, alignment, repeat shape, size up to 24 px, spacing, outline, brightness, inactive opacity and expanded offset. Outside pips are not width-clamped; check adjacent action bars. GCD prediction is retired; actual energy is shown. The planning regen assumption is unchanged.

Countdown (v0.21.1): free spells, including spells returning nil costs, no longer restart the timer. Cast-based protected snapshots reset only for confirmed positive energy costs. If a genuine spend's spell ID or cost is protected, the snapshot is retained rather than guessing; public energy drops still reset. See countdown cast reset diagnostics.

## v0.22.0 follow-up planning
In Ability planning > Configure repeat pips and follow-ups, select a source such as Gouge and set Follow-up window (1–10 seconds, default 1). Local rules use the configured assumed energy per GCD multiplied by the window in seconds (one-second Rogue GCD). Set the duration for your talents, allowing a safety margin. This is a static energy-budget estimate, not a live tick or CC prediction. Global reservations, repeats, Arsenal, and the live sweep are unchanged. Ability planning > Separate follow-up pip appearance provides an opt-in independent shape, size, spacing, alignment, placement, offset, outline, brightness and inactive opacity. Warning glyphs remain distinct; ability colors and overall opacity remain shared.

## v0.23.0 automatic follow-up timing
Each local relationship has Next GCD (1 second), Control window (known Gouge, Cheap Shot, Kidney Shot, Blind durations minus shared safety margin, default 0.5 seconds), or Custom. Supported control sources default to Control window except Kick targets. Longer v0.22 explicit windows are preserved as Custom. Gouge reads public Improved Gouge talent rank, or uses a labeled conservative base duration if unavailable. Kidney uses public target combo points; no prediction when protected or the window ends before GCD. Global rules/repeats unchanged. Assumed regeneration is not live; no prediction of DR, immunity, damage breaks, or positioning.
